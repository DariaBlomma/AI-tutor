# Спецификация: страница «Домашние задания» студента

**Версия:** 1.1
**Дата:** 26.11.2026
**Роль:** Студент
**Статус документа:** согласовано для разработки

---

## 1. Назначение страницы

Страница «Домашние задания» — главный рабочий экран студента. Здесь студент видит все задания, которые ему назначил учитель, и управляет их выполнением.

Страница закрывает три потребности студента:

1. Понять, **что нужно сделать сегодня** и в ближайшее время.
2. Проверить, **что уже сдано**.
3. **Найти старое задание** — например, то, что решал на прошлой неделе или в прошлом месяце.

В текущей версии страница предназначена только для студента. Отображение этого же списка глазами учителя будет добавлено отдельной задачей.

---

## 2. Жизненный цикл задания и статусы

Каждое задание находится в одном из пяти статусов. Статус определяется системой автоматически — по действиям студента и по дате дедлайна. Учитель и студент не могут менять статус вручную.

### 2.1. Что означает каждый статус

| Статус | Когда задание получает этот статус | Смысл для студента |
|---|---|---|
| **Новое** | Учитель назначил задание, студент его ещё не открывал, и дедлайн наступит не скоро (более чем через 14 дней). Либо у задания вообще нет дедлайна. | «Свежее задание, времени много, можно сделать позже». |
| **Скоро дедлайн** | Дедлайн наступит в течение 14 дней (включая сегодня), и студент ещё не начал задание. Сюда же попадают старые назначенные задания, которые студент так и не начал. | «Пора делать, времени мало». |
| **В процессе** | Студент открыл задание и начал его выполнять. Отдельного режима «просто посмотреть» нет: сам факт открытия означает начало работы. | «Я уже работаю над этим». |
| **Выполнено** | Студент ответил на все пункты задания. Отдельного подтверждения от учителя не требуется — сдал все пункты, значит выполнено. | «Готово, можно забыть». |
| **Просрочено** | Наступил дедлайн, а задание не выполнено. Присваивается автоматически. Вручную просрочить нельзя. | «Не успел, задание закрыто». |

### 2.2. Как статусы переходят друг в друга

Переходы возможны только вперёд, возврата назад нет (например, из «В процессе» обратно в «Новое» задание вернуться не может).

**Основные переходы:**

- Новое → В процессе (студент начал выполнять)
- Скоро дедлайн → В процессе (студент начал выполнять)
- В процессе → Выполнено (студент сдал все пункты)
- В процессе → Просрочено (дедлайн прошёл, задание не доделано)
- Новое → Просрочено (дедлайн прошёл, студент не начал)
- Скоро дедлайн → Просрочено (дедлайн прошёл, студент не начал)

### 2.3. Цветовое оформление

Каждый статус имеет собственный цвет бейджа, чтобы студент считывал состояние одним взглядом. Точные цвета задаются в дизайн-системе.

### 2.4. Задания без дедлайна

Учитель может назначить задание без дедлайна. Такие задания обязательно должны быть видны студенту.

Правило: задание без дедлайна не стареет. Пока оно не начато, оно всегда остаётся в статусе «Новое» — независимо от того, сколько дней прошло с момента назначения. Нет дедлайна — нет срочности и нет просрочки. Поэтому такое задание **никогда** не попадает в статусы «Скоро дедлайн» и «Просрочено».

В фильтре «Новое» для заданий без дедлайна ограничение по дате создания (14 дней) **не применяется** — они видны всегда, пока студент их не начал.

После начала выполнения задание без дедлайна ведёт себя как обычное: «В процессе» → «Выполнено».

## 3. Фильтры

Над списком расположены чипы-фильтры: **Все · Новое · Скоро дедлайн · В процессе · Выполнено · Просрочено**. Выбор фильтра показывает только задания в соответствующем статусе (по правилам из раздела 2).

### 3.1. Фильтр по дате

Дополнительный выбор периода доступен **только для двух статусов**:

- **Выполнено** — по **дате сдачи** (когда студент ответил на последний пункт). Позволяет найти, что решал на прошлой неделе или в прошлом месяце.
- **Просрочено** — по **дате дедлайна** (когда нужно было сдать). Позволяет найти, что было просрочено в выбранном периоде.

Для статусов **Новое, Скоро дедлайн, В процессе** отдельный выбор даты **недоступен**. Причина: временной смысл уже встроен в сам статус (например, «Новое» — это «назначено не более 14 дней назад»). Добавлять к этому ещё один выбор даты логически бессмысленно — студент не ищет «новое задание за прошлый месяц», потому что месяц назад назначенное задание уже не новое.

### 3.2. Готовые пресеты периода

Для «Выполнено» и «Просрочено» студент может выбрать период: **Сегодня · За неделю · За месяц · Произвольный диапазон** (выбор дат вручную). Произвольный диапазон должен корректно применяться к выбранному статусу.

---

## 4. Карточка задания

Каждое задание в списке показано карточкой. В карточке есть:

- **Название** задания (если названия нет — публичный идентификатор, например `TSK-1`).
- **Бейдж статуса** (цветной, см. 2.3).
- **Дедлайн** («до 20 ноября») либо «Без дедлайна», если дата не задана.
- **Тематические чипы** — краткое описание задания: тип упражнения (например, `GAP_FILL`, `WORD_FORMATION`), уровень сложности (например, `A1`, `A2`), грамматическая тема (например, `Present Simple`), лексическая тема (например, `Family`).
- **Прогресс** — сколько пунктов выполнено из общего числа (например, «0 / 3»). Пункты (предложения/подзадачи) создаёт учитель при создании задания.

---

## 5. Взаимодействие со списком

- **Клик по карточке.** Если задание «Новое», «Скоро дедлайн» или «В процессе» — студент переходит к выполнению (статус «Новое»/«Скоро дедлайн» при этом становится «В процессе»). Если «Выполнено» или «Просрочено» — студент переходит на страницу детального отчёта по заданию.
- **Действия прямо в списке.** Студент не может выполнить задание «галочкой» из списка или совершить иное действие, не заходя внутрь. Все действия — только внутри карточки.

---

## 6. Пагинация и пустое состояние

- Список разбивается на страницы (по умолчанию 10 заданий на странице), переключение — внизу.
- Если заданий нет или ни одно не подходит под фильтр, показывается дружелюбное сообщение: «Нет заданий».

---

## 7. Что должно храниться о задании для корректной работы

Чтобы статусы и фильтры считались правильно, по каждому назначению нужны: дата назначения, дата дедлайна (может отсутствовать), дата начала выполнения, дата сдачи, общее число пунктов и число выполненных пунктов.

---

## 8. Критерии приёмки

1. Студент видит все свои индивидуальные задания в корректных статусах.
2. Статусы определяются автоматически и меняются только по правилам раздела 2.2.
3. Фильтр по дате работает только для «Выполнено» (по дате сдачи) и «Просрочено» (по дате дедлайна); для остальных статусов недоступен.
4. Произвольный диапазон дат корректно применяется для «Выполнено» и «Просрочено».
5. Карточка показывает название, бейдж, дедлайн, тематические чипы и прогресс.
6. Задания без дедлайна видны, никогда не становятся «Скоро дедлайн» или «Просрочено» и не исчезают из фильтра «Новое» со временем.
7. Клик по незакрытому заданию начинает выполнение, клик по закрытому — открывает отчёт.
8. При отсутствии заданий показывается сообщение «Нет заданий».

## 9. Системный анализ (для разработчиков и AI-ассистентов)

Этот раздел описывает техническую логику фронтенда и пограничные случаи. Бэкенд считается готовым и стабильным. Цель раздела — чтобы любой разработчик или AI-ассистент, открыв этот файл, мог быстро понять, как устроена логика, и найти ответ при возникновении бага.

### 9.1. Модель данных (с точки зрения фронта)

Фронтенд получает от бэкенда список заданий. Каждое задание в ответе содержит следующие поля, необходимые для UI:

**Обязательные поля:**
- `id` — уникальный идентификатор задания.
- `name` — название задания (может быть пустым, тогда используется `publicId`).
- `publicId` — публичный идентификатор (например, `TSK-1`).
- `status` — бэкенд-статус (`ASSIGNED`, `IN_PROGRESS`, `COMPLETED`, `EXPIRED`).
- `deadline` — дата дедлайна в ISO-формате (может быть `null`).
- `createdAt` — дата создания задания в ISO-формате.
- `completedAt` — дата выполнения в ISO-формате (может быть `null`, если не выполнено).
- `startedAt` — дата начала выполнения в ISO-формате (может быть `null`).
- `totalItems` — общее количество пунктов в задании.
- `completedItems` — количество выполненных пунктов.

**Дополнительные поля (для карточки):**
- `type` — тип задания (например, `GAP_FILL`, `WORD_FORMATION`).
- `level` — уровень сложности (например, `A1`, `A2`).
- `grammarTopic` — грамматическая тема (например, `Present Simple`).
- `lexicalTopic` — лексическая тема (например, `Family`).

**Вычисляемые поля (фронтенд определяет сам):**
- `uiStatus` — UI-статус бейджа (`new`, `urgent`, `in-progress`, `completed`, `overdue`). Вычисляется по правилам из раздела 9.2.
- `progress` — строка вида «N / M» для отображения в карточке.

### 9.2. Маппинг статусов (бэкенд → UI)

Фронтенд определяет UI-статус бейджа на основе бэкенд-статуса и дат. Логика строго детерминирована:

**Правила вычисления `uiStatus`:**

1. Если `status === 'IN_PROGRESS'` → `uiStatus = 'in-progress'`.
2. Если `status === 'COMPLETED'` → `uiStatus = 'completed'`.
3. Если `status === 'EXPIRED'` → `uiStatus = 'overdue'`.
4. Если `status === 'ASSIGNED'`:
   - Если `deadline === null` → `uiStatus = 'new'` (задание без дедлайна всегда «Новое», пока не начато, независимо от даты создания).
   - Вычислить `daysUntilDeadline` — количество полных дней до дедлайна (отрицательное = дедлайн прошёл, `Infinity` = дедлайна нет).
   - Если `daysUntilDeadline >= 0 && daysUntilDeadline <= 14` → `uiStatus = 'urgent'`.
   - Если `daysUntilDeadline > 14 && isCreatedRecently(createdAt)` → `uiStatus = 'new'`.
   - Иначе → `uiStatus = 'urgent'`.

**Вспомогательные функции:**
- `daysUntilDeadline(deadline)`: разница в днях между сегодня (00:00:00) и дедлайном (00:00:00). Если дедлайна нет — `Infinity`.
- `isCreatedRecently(createdAt)`: `createdAt >= сегодня минус 14 дней`.

**Константы:**
- `URGENT_DEADLINE_DAYS = 14`.
- `CREATED_RECENTLY_DAYS = 14`.

### 9.3. Логика фильтрации (чипы → параметры API)

При выборе чипа статуса фронтенд формирует запрос к `GET /api/student/homework` с определёнными параметрами. Глобальный выбор даты (`datePreset` или `custom` диапазон) применяется **только для статусов `completed` и `overdue`**.

**Таблица маппинга:**

| Чип (UI) | Параметр `status` | Параметры дат |
|---|---|---|
| `all` | не передаётся | не передаются |
| `new` | `ASSIGNED` | `createdAtFrom = сегодня - 14 дней`, `deadlineExcludeFrom = сегодня + 14 дней` |
| `urgent` | `ASSIGNED` | `deadlineFrom = сегодня (00:00:00)`, `deadlineTo = сегодня + 14 дней (00:00:00)` |
| `in-progress` | `IN_PROGRESS` | **Параметры дат не передаются.** Только `status`. |
| `completed` | `COMPLETED` | `completedAtFrom` и `completedAtTo` берутся из выбранного `datePreset` или `custom` диапазона. |
| `overdue` | `EXPIRED` | `deadlineFrom` и `deadlineTo` берутся из выбранного `datePreset` или `custom` диапазона. |

**Правила обработки выбора даты:**
- Если выбран чип `completed` → значения `from` и `to` из диапазона маппятся в `completedAtFrom` и `completedAtTo`.
- Если выбран чип `overdue` → значения `from` и `to` из диапазона маппятся в `deadlineFrom` и `deadlineTo`.
- Если выбран любой другой чип (`all`, `new`, `urgent`, `in-progress`) → пользовательский выбор даты **игнорируется**. Используются только жёстко заданные для чипа правила.

**Пресеты дат:**
- `today` — сегодня.
- `week` — последние 7 дней.
- `month` — последние 30 дней.
- `custom` — произвольный диапазон (выбирается вручную).

**Пагинация и сортировка:**
- Параметры `page` (начиная с 0) и `size` (по умолчанию 10) передаются в каждом запросе.
- Сортировка жёстко задана: `sortBy = 'createdAt'`, `sortDirection = 'desc'`.

### 9.4. Пограничные случаи и правила обработки

**Задания без дедлайна (`deadline === null`):**
- Никогда не попадают в UI-статусы `urgent` и `overdue`.
- Всегда отображаются как `new` (пока не начаты) — **без ограничения по дате создания**.
- После начала выполнения отображаются как `in-progress`.
- В фильтре `urgent` не показываются (нет дедлайна — нет срочности).
- В фильтре `overdue` не показываются (нет дедлайна — нет просрочки).
- В фильтре `new` показываются всегда, пока не начаты (ограничение `createdAtFrom = сегодня - 14 дней` для них не применяется).

**Переходы статусов:**
- Переходы только вперёд, возврата назад нет.
- `new` / `urgent` → `in-progress`: когда студент открывает задание.
- `in-progress` → `completed`: когда студент отвечает на последний пункт.
- `in-progress` → `overdue`: когда наступает дедлайн, а задание не выполнено.
- `new` / `urgent` → `overdue`: когда наступает дедлайн, а студент не начал.

**Удаление задания учителем:**
- Задание можно удалить, только если оно не начато студентом (статус `ASSIGNED` на бэке).
- Если задание в статусе `IN_PROGRESS` — удаление запрещено.

**Пустое состояние:**
- Если заданий нет или ни одно не подходит под фильтр → показать сообщение «Нет заданий».

**Ошибки загрузки:**
- Если запрос к API вернул ошибку → показать сообщение «Ошибка загрузки данных».

### 9.5. Контракты с бэкендом

**Запрос:**
- Метод: `GET`.
- URL: `/api/student/homework` (или аналогичный эндпоинт).
- Параметры:
  - `page` (number, начиная с 0).
  - `size` (number, по умолчанию 10).
  - `status` (string, опционально: `ASSIGNED`, `IN_PROGRESS`, `COMPLETED`, `EXPIRED`).
  - `deadlineFrom` (ISO-дата, опционально).
  - `deadlineTo` (ISO-дата, опционально).
  - `deadlineExcludeFrom` (ISO-дата, опционально).
  - `createdAtFrom` (ISO-дата, опционально).
  - `completedAtFrom` (ISO-дата, опционально).
  - `completedAtTo` (ISO-дата, опционально).
  - `sortBy` (string, по умолчанию `createdAt`).
  - `sortDirection` (string, по умолчанию `desc`).

**Ответ:**
- Структура: пагинированный список заданий.
- Поля каждого задания: см. раздел 9.1.
- Метаданные пагинации: `totalElements`, `totalPages`, `page`, `size`.

**Обработка ошибок:**
- `401 Unauthorized` → перенаправление на страницу входа.
- `403 Forbidden` → сообщение «Нет доступа».
- `500 Internal Server Error` → сообщение «Ошибка загрузки данных».

### 9.6. Правила UI-поведения

**Отображение фильтров:**
- Чипы статусов всегда видны.
- Выбор даты (`datePreset` или `custom`) виден **только** для чипов `completed` и `overdue`.
- Для остальных чипов (`all`, `new`, `urgent`, `in-progress`) выбор даты скрыт или неактивен.

**Обновление списка:**
- После смены чипа статуса → сброс на первую страницу (`page = 0`), запрос к API.
- После смены даты → сброс на первую страницу (`page = 0`), запрос к API.
- После смены страницы → запрос к API с новым `page`.

**Клик по карточке:**
- Если `uiStatus === 'new'` или `'urgent'` или `'in-progress'` → переход на страницу выполнения задания.
- Если `uiStatus === 'completed'` или `'overdue'` → переход на страницу детального отчёта по заданию.

**Прогресс-бар:**
- Отображается всегда, если `totalItems > 0`.
- Формат: «`completedItems` / `totalItems`».
- Если `totalItems === 0` → прогресс-бар не отображается.

## 10. Тестирование логики чипов фильтров

Этот раздел описывает, какие сценарии должны быть покрыты тестами для уверенности в корректной работе фильтрации. Тесты делятся на unit-тесты (логика маппинга и формирования параметров) и интеграционные/e2e-тесты (поведение UI).

### 10.1. Unit-тесты: маппинг чипов в параметры API

**Что тестировать:** функцию/хук, который по выбранному чипу и диапазону дат формирует объект параметров для API.

**Сценарии:**

| # | Вход | Ожидаемый результат |
|---|---|---|
| 1 | Чип `all`, без даты | `status` не передан, параметры дат не переданы |
| 2 | Чип `new`, без даты | `status = ASSIGNED`, `createdAtFrom = сегодня - 14д`, `deadlineExcludeFrom = сегодня + 14д` |
| 3 | Чип `urgent`, без даты | `status = ASSIGNED`, `deadlineFrom = сегодня`, `deadlineTo = сегодня + 14д` |
| 4 | Чип `in-progress`, без даты | `status = IN_PROGRESS`, **параметры дат не переданы** |
| 5 | Чип `completed`, пресет `week` | `status = COMPLETED`, `completedAtFrom = сегодня - 7д`, `completedAtTo = сегодня` |
| 6 | Чип `completed`, `custom` диапазон 01.10–31.10 | `status = COMPLETED`, `completedAtFrom = 01.10`, `completedAtTo = 31.10` |
| 7 | Чип `overdue`, пресет `month` | `status = EXPIRED`, `deadlineFrom = сегодня - 30д`, `deadlineTo = сегодня` |
| 8 | Чип `overdue`, `custom` диапазон | `status = EXPIRED`, `deadlineFrom/To` из custom-диапазона |
| 9 | Чип `new`, выбран пресет `week` | Пресет игнорируется. Параметры те же, что в сценарии 2. |
| 10 | Чип `in-progress`, выбран `custom` диапазон | Пресет игнорируется. Параметры те же, что в сценарии 4. |

### 10.3. Интеграционные / E2E тесты (поведение UI)

**Сценарии:**

1. **Видимость выбора даты.**
   - При клике на чип `completed` или `overdue` — компонент выбора даты становится видимым/активным.
   - При клике на чип `new`, `urgent` или `in-progress` — компонент выбора даты скрывается/становится неактивным, а если был выбран ранее — сбрасывается (или игнорируется при запросе).

2. **Сброс пагинации.**
   - Пользователь находится на странице 3. Меняет чип статуса или пресет даты → пагинация сбрасывается на страницу 1, отправляется новый запрос с `page=0`.

3. **Отображение заданий без дедлайна.**
   - Создать задание без дедлайна. Убедиться, что оно отображается с бейджем «Новое».
   - Применить фильтр «Скоро дедлайн» → задание исчезает из списка.
   - Применить фильтр «Новое» → задание остаётся в списке (даже если прошло больше 14 дней с момента создания).

4. **Переход по клику.**
   - Клик по карточке со статусом `new` / `urgent` / `in-progress` → редирект на страницу выполнения.
   - Клик по карточке со статусом `completed` / `overdue` → редирект на страницу детального отчёта.

5. **Пустое состояние.**
   - Применить фильтр, по которому нет заданий (например, «Выполнено» за прошлый год, если таких нет) → отображается блок «Нет заданий», а не бесконечный спиннер или пустой экран.
