# План: Исправление check constraint для статуса FAILED

## Проблема
При f Submit ответа с исчерпанием лимита подсказок (3) или попыток (3) бэкенд пытается установить статус `FAILED`, но база данных отклоняет это из-за check constraint, который разрешает только 3 статуса.

## Корневая причина
**Файл:** `backend/src/main/resources/db/changelog/changes/008-create-student-work-item-progress-table.sql`

```sql
CHECK (status IN ('NOT_STARTED', 'IN_PROGRESS', 'SOLVED'))
```

В коде (Java enum `ItemProgressStatus`) определено **4 статуса**, включая `FAILED`, но DB constraint разрешает только 3.

## Решение
Создать новый Liquibase migration файл **024** для обновления check constraint.

### Шаги выполнения

#### 1. Создать migration файл
**Путь:** `backend/src/main/resources/db/changelog/changes/024-add-failed-status-to-progress-check.sql`

Содержимое:
```sql
-- liquibase formatted sql

--changeset daria:024-add-failed-status-to-progress-check
--comment: Добавить статус FAILED в check constraint для student_work_item_progress
ALTER TABLE student_work_item_progress
    DROP CONSTRAINT student_work_item_progress_status_check;

ALTER TABLE student_work_item_progress
    ADD CONSTRAINT student_work_item_progress_status_check
        CHECK (status IN ('NOT_STARTED', 'IN_PROGRESS', 'SOLVED', 'FAILED'));

--rollback ALTER TABLE student_work_item_progress DROP CONSTRAINT student_work_item_progress_status_check;
--rollback ALTER TABLE student_work_item_progress ADD CONSTRAINT student_work_item_progress_status_check CHECK (status IN ('NOT_STARTED', 'IN_PROGRESS', 'SOLVED'));
```

#### 2. Проверить主 изменения в коде
Убедиться, что все места, где используется `FAILED`, согласованы:
- `StudentExecutionService.java` — уже использует `FAILED` в методах `submit()`, `complete()`, `isAllSolved()` ✓
- `ItemProgressStatus.java` enum — уже содержит `FAILED` ✓

#### 4. Тестирование
1. Запустить бэкенд с новой миграцией
2. Выполнить сценарий:
   - Начать выполнение задания
   - Ответить неверно 3 раза (или с 3 подсказками)
   - Убедиться, что статус успешно устанавливается в `FAILED` (без 500 ошибки)
3. Проверить завершение работы — `complete()` должен корректно обрабатывать `FAILED` пункты

### Критические файлы для изменения
- **Создать:** `backend/src/main/resources/db/changelog/changes/024-add-failed-status-to-progress-check.sql`
- **Проверить:** `backend/src/main/java/com/aitutor/backend/services/student/StudentExecutionService.java` (уже использует FAILED)
- **Проверить:** `backend/src/main/java/com/aitutor/backend/enums/ItemProgressStatus.java` (уже содержит FAILED)

### Примечания
- Миграция идемпотентна: повторный запуск без изменений
- Rollback SQL включен для удобства отката
- Статус `FAILED` уже интегрирован в бизнес-логику — только DB constraint требует обновления
