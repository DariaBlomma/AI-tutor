# План: Студенческая страница выполнения задания (Work Execution Flow)

## Контекст

- **Бэкенд** уже имеет полный flow: start → submit → complete → summary
- **AnswerChecker** использует ExactMatchChecker (без ИИ, тариф пока не реализован)
- **Подсказки** — placeholder (будущий ИИ)
- **Навигация:** клик по заданию на дашборде → `/student/work/:workId` → auto-start → execution page
- **Результаты:** используем существующий backend summary endpoint
- **Имя учителя не отображается**

---

## Шаг 1: Типы

**Создать:** `src/student/types/work.ts` — расширить существующий файл.

Добавить DTO, зеркалящие Java-DTO бэкенда:
- `WorkItemType` = 'WORD_FORMATION' | 'GAP_FILL' | 'TFNS' | 'MATCHING'
- `StudentWorkDetailResponse` — детальная информация о работе (items без correctAnswer)
- `StudentWorkProgress` — прогресс (currentItemIndex, totalItems, solvedItems)
- `StudentTaskItemDto` — пункт без correctAnswer
- `StudentSubmitAnswerRequest` / `StudentSubmitAnswerResponse`
- `StudentWorkSummaryResponse` / `StudentWorkSummaryItemDto`

**Модифицировать:** `src/student/types/models/index.ts` — реэкспорт новых типов.

---

## Шаг 2: Сервисный слой

**Создать:** `src/student/services/StudentWorkService.ts`

Методы:
- `getWorkDetail(workId)` — GET /student/work/{workId}
- `startWork(workId)` — POST /student/work/{workId}/start
- `submitAnswer(workId, itemId, data)` — POST /student/work/{workId}/items/{itemId}/submit
- `completeWork(workId)` — POST /student/work/{workId}/complete
- `getWorkSummary(workId)` — GET /student/work/{workId}/summary

---

## Шаг 3: Хук выполнения

**Создать:** `src/student/hooks/useWorkExecution.ts`

Хук принимает `workId`, управляет:
- Загрузкой work detail через `useQuery`
- Автостартом работы при монтировании
- Состоянием текущего пункта и ответа
- Мутациями: start, submit, complete
- Состоянием фидбека (правильно/неправильно)
- Навигацией к результатам когда все пункты решены

---

## Шаг 4: Обновление BackLink

**Модифицировать:** `src/tasks/ui/widgets/BackLink/BackLink.tsx` — добавить optional prop `to` с дефолтом `/`.

## Шаг 5: Страница выполнения (WorkExecutionView)

**Создать:** `src/student/ui/views/WorkExecutionView/`

Файлы:
- `WorkExecutionView.tsx` — основная страница
- `WorkExecutionView.module.scss` — стили
- `index.ts` — реэкспорт

Компонент включает:
- BackLink на дашборд
- Header: название задания + TaskPreviewChips (levels, topics, itemTypes, isMixed)
- Progress bar: пункт X из Y, решено N/Y
- Position card: номер, тип механики, prompt, input для ответа
- Feedback при неправильном ответе
- Hints section (disabled placeholder)
- Кнопки: «Проверить» / «Далее»

**Важно:** Teacher name НЕ отображается.

1. `npx tsc -b && npm run build` — без ошибок

4. Правильный ответ → кнопка «Далее» → следующий пункт
5. Все пункты решены → редирект на страницу результатов
6. Результаты показывают статистику из backend summary
7. BackLink возвращает на дашборд
8. Bottom nav показывает активный пункт «ДЗ»
