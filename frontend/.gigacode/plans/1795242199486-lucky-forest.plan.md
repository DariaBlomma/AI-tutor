# План: модуль `reports` — страница отчёта по отдельному заданию

## Контекст

- **Цель:** создать страницу детального отчёта по выполненной работе (уровень 3 из TeacherReportController).
- **Общая для teacher и student** — оба видят один и тот же UI.
- **Backend API уже готов:** `GET /teacher/students/{studentId}/work/{workId}/report` → `WorkReportDetailDto`.
- **Данные из DTO:** task name, student name, topics, task types, isMixed, context (instruction + material), items (position, prompt, itemType, correctAnswer, studentAnswer, correct, attemptsCount, hintsGiven), durationSeconds, errorsCount, aiComment.

## Роутинг

Создаём два роута (общий контент, но разные пути с guard'ами):
- `/teacher/reports/:studentId/work/:workId` — для учителя
- `/student/reports/:workId` — для ученика

**Вариант A (предпочтительный):** один общий компонент `ReportDetailView`, который рендерится на обоих роутах. Guard'ы в loader'ах.

**Пути:**
- `src/routes/teacher/reports/:studentId/work/$workId.tsx`
- `src/routes/student/reports/$workId.tsx`

**Навигация:** добавляем пункт «Отчёт» в `AppBottomNav` для student (если ещё нет отдельной страницы результатов).

## Компоненты

### 1. `ReportDetailView` (страница)

**Структура:**
```
<div className={styles.page}>
  <BackLink />
  <ReportSummary />        ← task name, student name (teacher), время, ошибки, позиции
  <ReportTaskPreview />    ← instruction (если есть) + context (material)
  <ReportPositionList />   ← список ReportPositionItem
  <ReportAiComment />      ← placeholder
</div>
```

**Стиль:**
- Адаптив: полная ширина, без `max-width`, `padding: 20px` по бокам.
- Использовать CSS-переменные из `variables.scss`: `--p`, `--c1`, `--c3`, `--err`, `--ok`.
- Чипы (levels, topics, task types, mechanics) — переиспользовать `TaskPreviewChips` из `@/tasks/ui/widgets/TaskPreviewChips/TaskPreviewChips`.

### 2. `ReportSummary` (widget)

**Содержимое:**
- Заголовок: название задания (`taskName`)
- Подзаголовок: имя ученика (только для teacher — `studentName`)
- Мета-теги: чипы через `TaskPreviewChips` (levels, examType?, grammarTypes, topics, itemTypes, isMixed)
- Сводка в строку/сетку:
  - Время: `formatDuration(durationSeconds)` → «8 мин 30 с»
  - Ошибки: `errorsCount`
  - Позиции: `${solvedItems ?? items.length} / ${items.length}`

### 3. `ReportTaskPreview` (widget)

**Логика (по аналогии с TaskDetailView):**
- Если `instruction` (из `context` или отдельного поля) есть → показать секцию «Описание» с текстом.
- Если `context` (material) есть → показать секцию «Материал» с title + text.
- **Без эталонного ответа** (user убрал).

### 4. `ReportPositionItem` (widget)

**Структура для каждой позиции:**
```
<div className={styles.positionItem}>
  <div className={styles.positionHeader}>
    <span>Позиция {position} · {mechanicLabel}</span>
    <span className={correct ? styles.correct : styles.wrong}>✓/✗</span>
  </div>
  <p className={styles.prompt}>{prompt}</p>
  <div className={styles.answers}>
    <div className={styles.studentAnswer}>
      <span>Ответ ученика:</span> <strong>{studentAnswer}</strong>
    </div>
    {correctAnswer && (
      <div className={styles.correctAnswer}>
        <span>Правильный:</span> <strong>{correctAnswer}</strong>
      </div>
    )}
  </div>
  {attemptsCount > 1 && (
    <div className={styles.attempts}>
      <span>Попыток: {attemptsCount}</span>
    </div>
  )}

</div>
```

**Примечания:**
- **Подсказки не показываем вообще.**
- **Попытки:** показываем только общее количество (`attemptsCount > 1`).
- **Эталон:** показываем всегда (по решению заказчика из backend-комментария).

## Сервис и хук

### `ReportsService`

```typescript
const REPORTS_PATH = '/teacher'; // базовый путь

class ReportsService {
    static async getWorkReportDetail(
        studentId: number,
        workId: number,
    ): Promise<WorkReportDetailDto> {
        const response = await api.get<WorkReportDetailDto>(
            `${REPORTS_PATH}/students/${studentId}/work/${workId}/report`
        );
        return response.data;
    }
}
```

### `useReportDetail`

```typescript
function useReportDetail(
    studentId: number | null,
    workId: number | null,
): {
    report: WorkReportDetailDto | null;
    isLoading: boolean;
    isError: boolean;
}
```

- `studentId` может быть `null` для student-роута (тогда ID берём из токена).
- Использовать паттерн `useTeacherReports`: fetcher внедряется извне, хук только управляет состоянием.
